# Дизайн-система langlab

Маленькая система под конкретный продукт: учебный контент, светлая и тёмная тема,
телефон как основной экран. Не фреймворк — набор решений, которые уже приняты,
чтобы каждый новый экран не начинался с нуля.

Живые образцы: **[/styleguide.html](../styleguide.html)** — рендерится из тех же файлов,
что и сайт. Разошлось с сайтом — значит что-то сломано.

## Как устроены файлы

| файл | что внутри | правило |
|---|---|---|
| `tokens.css` | палитра → роли → шкалы | единственное место с сырыми цветами и размерами |
| `base.css` | сброс, каркас, типографика, шапка | только теги и каркасные классы |
| `primitives.css` | кнопка, карточка, поле, чип, прогресс… | у каждого примитива описаны **все** состояния |
| `content.css` | роли учебного контента | язык, которым размечены уроки |
| `patterns.css` | сборки: экран урока, карта времён, разбор | комбинации примитивов, а не новые кирпичи |
| `icons.js` | один набор иконок | никаких юникодных `‹ › ✓` в разметке |

Порядок подключения в `index.html` именно такой: токены → база → примитивы → контент →
паттерны. Каскад работает сверху вниз, ничего не перебивается через `!important`.

## Цвет — это роль

В компонентах не бывает `#ffd233` и не бывает `--c-orange`. Бывает `--surface-raised`,
`--border`, `--text-dim`, `--danger`, `--accent`. Если нужного смысла нет — **заводим роль
в `tokens.css`**, а не красим по месту.

- **Поверхности:** `--surface` (страница) → `--surface-sunken` (поля, вдавленное) →
  `--surface-raised` (карточки) → `--surface-active` (выбранное).
- **Текст:** четыре ступени, `--text` → `--text-soft` → `--text-dim` → `--text-faint`.
  Пятой не будет: если текст не влезает в четыре уровня важности, проблема в тексте.
- **`--accent` задаёт экран.** Урок красится цветом своего аспекта, тест — своего.
  Один экран = один акцент, поэтому кнопка, активная строка и подчёркивание в примере
  всегда одного цвета. Ставится инлайном: `style="--accent:${course.accentFor(lesson)}"`.
- **Состояния ответа** — `--success` / `--danger` / `--warn`, и только они. Правильный
  ответ везде зелёный, неправильный везде красный, без исключений «здесь красивее синий».
- **Палитра курса** (`--c-blue`, `--c-green`…) — смысловые цвета контента. Их назначает
  курс в `content/<курс>/index.js`, движок знает только имена.

Светлая и тёмная описаны через `light-dark()` — одна строка на токен. Отдельной тёмной
темы «где-то ниже» нет и заводить не надо.

## Типографика: восемь ступеней

`--fs-1` … `--fs-8`. Произвольные `clamp()` и `font-size: 17px` по месту — запрещены:
через месяц это превращается в двенадцать почти одинаковых заголовков.

| роль | класс / тег | ступень |
|---|---|---|
| заголовок экрана | `h1` | `--fs-8` |
| заголовок секции | `h2`, `.h-sm` | `--fs-7` |
| заголовок карточки | `h3`, `.card-title` | `--fs-5` |
| надзаголовок | `.eyebrow` | `--fs-1`, капс, разрядка |
| вводный абзац | `.lede` | `--fs-5`, ширина ≤ 62 символа |
| основной текст | `.body` | `--fs-4` |
| фраза на языке | `.en` | `--fs-6`, моноширинный |
| перевод | `.ru` | `--fs-3`, курсив |
| служебное | `.caption`, `.kicker` | `--fs-1` |

Моноширинный — не для красоты: им набирается всё, что читается как **данные** (фразы
на изучаемом языке, счёт, метки). Пропорциональный — всё, что читается как речь.

## Состояния

У примитива их восемь, и они описаны рядом, а не дописываются в компонентах:

`default` · `hover` (только под `@media (hover: hover)`) · `active` · `disabled` ·
`focus-visible` · `is-selected` · `is-correct` · `is-wrong`.

Именование: состояние — это `is-*` (`.opt.is-correct`), вариант — это модификатор
(`.btn-primary`). Так видно, что меняется во времени, а что задано разметкой.

**Выключенная кнопка не бледное главное действие.** У `.btn:disabled` снимается заливка
совсем: полупрозрачный акцент читается как «можно нажать», и человек тыкает в мёртвую кнопку.

## Ритм и размеры

- Сетка 4 px: `--s-1` (4) … `--s-9` (96). Промежуточных значений нет.
- Внутри карточки — `--s-4`, между блоками — `--s-5`, между секциями — `--s-7`/`--s-9`.
- `--tap: 44px` — минимальная площадь нажатия. Любая кнопка, вкладка и строка списка
  обязаны в неё попадать; это не рекомендация, а нижняя граница.
- `--maxw-text: 62ch` для читаемого текста, `--maxw-stage: 640px` для рабочей области
  урока и теста.

## Движение

Три длительности и одна кривая: `--dur-1` (120 мс, отклик), `--dur-2` (240 мс, появление),
`--dur-3` (420 мс, смена шага), `--ease`. Ступенчатое появление блоков — максимум 225 мс
на весь каскад: длиннее — и быстрое листание ощущается тормозом.

`prefers-reduced-motion` глушит всё это глобально в `tokens.css` — отдельно в компонентах
проверять не нужно.

## Mobile-first

Базовые правила пишутся для телефона, медиа-запросы — только вверх (`min-width`).
Брейкпоинты: **560** (сетка карточек), **720** (плотность, крупная типографика),
**900** (двухколоночные сборки вроде карты времён).

`hover` — только внутри `@media (hover: hover)`: на тачскрине он залипает после тапа.

## Роли контента

Автор урока пишет смысл, а не оформление:

```js
{ type: 'examples', items: [
  { en: 'I <u>have submitted</u> my application.', ru: 'я подал заявку' },
]}
```

`<u>` — ключевая форма (красится акцентом), `<b>` — усиление, `.slot` — правая часть
формулы, `.en` / `.ru` — фраза и перевод. Новый тип шага добавляется в `engine/steps.js`
и оформляется в `content.css` — в остальных файлах ему делать нечего.

## Чек-лист нового экрана

1. Один акцент на экран, задан через `--accent`.
2. Заголовок из шкалы, `.eyebrow` над ним, `.lede` под ним.
3. Главное действие — ровно одно, `.btn-primary`. Остальные — `secondary` / `ghost`.
4. Есть пустое состояние, и в нём есть выход (`.empty` + кнопка).
5. Есть состояние ошибки сети — текстом, а не пустотой.
6. Проверено на 375 px и в обеих темах.
7. Заголовок вкладки называет экран (см. `startRouter`).
